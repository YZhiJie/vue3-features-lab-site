手写响应式原理（mini reactivity） ​

特性 02 教的是怎么用 shallowRef / customRef / effectScope，这一章把 Vue 响应式系统亲手写一遍（约 60 行），建立心智模型：为什么改数据 视图会更新、computed 为什么是「懒」的、依赖为什么能精确到字段。

三个核心概念 ​

effect（副作用）  ──读数据时──▶  track（依赖收集）：把当前 effect 登记到「数据→属性」表里
数据被修改        ──▶ trigger（派发更新）：从表里找出登记过的 effect，重新执行
  1. effect(fn)：注册一个副作用，立即执行一次。执行期间它是 「当前活跃副作用」（全局变量 activeEffect）。
  2. track(target, key)：数据被读取时调用，把 activeEffect 记到 targetMap 中对应对象、对应属性的依赖集合里。
  3. trigger(target, key)：数据被写入时调用，把该属性依赖集合里的 effect 全部重新执行一遍。

数据结构：三层嵌套 ​

targetMap: WeakMap<目标对象, Map<属性名, Set<副作用函数>>>
  • 外层 WeakMap：对象被回收时，它的依赖记录自动消失（不阻止 GC）；
  • 中层 Map：一个对象的每个 key 一条依赖；
  • 内层 Set：一个 key 可被多个 effect 依赖，天然去重。

这就是「依赖精确到字段」的秘密：改 state.a 只会触发依赖了 a 的 effect，读 state.b 不会被牵连。

reactive：Proxy 拦截 get/set ​

ts
new Proxy(obj, {
  get(target, key, receiver) {
    track(target, key)        // 读 → 收集
    return Reflect.get(target, key, receiver)
  },
  set(target, key, value, receiver) {
    const ok = Reflect.set(target, key, value, receiver)
    trigger(target, key)      // 写 → 派发
    return ok
  },
})

Vue 2 的 Object.defineProperty 只能拦截「已知属性」，所以数组下标、 新增属性需要 $set；Proxy 代理整个对象，新增属性 / 下标赋值天然可拦截。

ref：每个实例一个 dep 集合 ​

ref 没有 key 结构，本质是个带 getter/setter 的对象，闭包里持有 一个 Set：get 时把 activeEffect 加进去，set 时值变了就派发。

computed：lazy + dirty 缓存 ​

computed 不立刻求值，内部维护 dirty 标志：

  • 被读取且 dirty=true：执行 getter 算一次，缓存结果，置 dirty=false；
  • 被读取且 dirty=false：直接返回缓存（不重算）；
  • 上游依赖变化时，一个内部 effect 只做一件事：把 dirty 重新置 true， 并通知「依赖了这个 computed 的下游 effect」。

所以 computed 是**拉取式（pull-based）**的：没人读就不算；连续改十次 上游再读一次，也只在读取时算一次。

与 Vue 真实实现（@vue/reactivity）的差距 ​

本实现是教学简化版，生产级实现还多了：

  • effect 的依赖清理（dep cleanup）：分支读取（a ? b : c）后， 旧分支的依赖要能摘除，真实实现让每次重跑前清空再收集；
  • scheduler 调度器：trigger 不直接跑 effect，而是推入任务队列去重， 在 nextTick 批量 flush —— 这是「多次改数据只渲染一次」的来源；
  • 嵌套 effect 栈：真实实现用栈管理 activeEffect，本练习只在 computed 里用「保存/恢复」简化处理；
  • 版本计数双向链表：Vue 3.5 重构依赖结构，内存降约 56%，深层数组 追踪最高快 10 倍（本练习的 Set 模型更好懂，但不是 3.5 的物理结构）。

常见坑（真实踩坑记录） ​

  • track 时 activeEffect 是 null：依赖收集只在 effect 同步执行期间 发生；在 setTimeout/Promise 回调里读数据不会被收集（真实 Vue 同理， watch 的 getter 只在同步阶段建立依赖）。
  • trigger 时直接用新数组替换 dep：遍历过程中派发可能引起集合变化， 要遍历快照或用稳定迭代（本练习 Set.forEach 期间不修改集合，安全）。
  • computed 重算时没恢复外层 activeEffect：getter 跑完后外层 effect 丢了，之后的 track 全部登记错对象。进入 computed 前保存、出来后恢复。
  • ref 的 set 不做值比较：赋相同的值也派发，造成死循环式更新； 先判断 v === _value。
  • 把 targetMap 设计成普通对象：键只能是字符串且阻止目标对象被 GC； 以对象为键的表必须用 Map/WeakMap。
