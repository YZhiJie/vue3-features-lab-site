模板引用与 useTemplateRef ​

这是什么 ​

响应式数据管「状态」，但总有些事必须直接摸到 DOM 元素：聚焦输入框、读取宽度、滚动到某一项、调用第三方 DOM 库的初始化。模板引用（template ref）就是 Vue 给你的「DOM 握手通道」。

Vue 3.5 带来了新的 useTemplateRef API，一句话改进：把「变量名必须与 ref 同名」的隐式约定，换成了显式的字符串 key。

vue
<script setup lang="ts">
import { onMounted, useTemplateRef } from 'vue'

// 旧写法（3.0 起）：变量名必须与模板里的 ref="inputEl" 一模一样才能对上
// const inputEl = ref<HTMLInputElement | null>(null)

// 新写法（3.5 起）：变量随便叫，字符串 key 才是与模板的连接点
const inputEl = useTemplateRef<HTMLInputElement>('inputEl')

onMounted(() => {
  inputEl.value?.focus() // 挂载后 ref 一定有值（前提：元素无条件渲染）
})
</script>

<template>
  <input ref="inputEl" />
</template>

核心 API 速览 ​

API用途关键点
useTemplateRef(key)按字符串 key 拿模板 ref（3.5）参数必须与 ref="key" 一字不差；返回只读浅 ref
ref(null)旧方式：同名变量自动关联仍然可用；变量名 = 连接约定
:ref="fn"函数 ref每次渲染都会调用，参数是元素或 null
onMounted(fn)ref 可用的最早时机挂载前 ref 是 null；v-if 的元素随条件出现/消失

新旧怎么选？ 3.5 之后新代码一律用 useTemplateRef：显式 key、改名安全、useTemplateRefsList 等配套更自然；维护旧代码遇到 ref(null) 不必强改。

函数 ref：字符串 ref 覆盖不了的场景 ​

v-for 收集、动态挂载、按 key 精确对应……这些场景函数 ref 都能接住：

vue
<template>
  <!-- 每次渲染都会调用：el 是元素或 null -->
  <li v-for="item in items" :key="item.id" :ref="(el) => collect(item.id, el)">
    {{ item.text }}
  </li>
</template>

<script setup lang="ts">
const els = ref(new Map<number, HTMLElement>())
function collect(id: number, el: unknown) {
  const li = el as HTMLElement | null
  li ? els.value.set(id, li) : els.value.delete(id) // null = 该槽位即将卸载
}
</script>

要点：用业务 id 而不是数组下标做 Map 的 key。列表排序 / 增删时下标会变，旧元素还挂在旧下标上就「错位」了；用 id 收集天然稳定。

新旧写法差异速记 ​

维度ref(null) 旧写法useTemplateRef(key)
连接方式变量名与 ref 字符串同名（隐式）显式字符串 key（改名安全）
变量命名被模板占用，不能随便起名随意，key 才是身份标识
返回值普通可写 ref只读浅 ref（防误赋值）
拼错后果变量名对不上时 ref 悄悄失联key 拼错同样静默失败，都要靠自检

常见坑（真实踩坑记录） ​

  • key 拼错静默失败：useTemplateRef('inpuEl') 少打一个字母，不报错、不警告，value 永远是 null——这是新 API 最大的坑，排查时先对字符串。
  • 挂载前 / v-if 下访问 ref：onMounted 之前 ref 是 null；被 v-if 控制的元素卸载后也变回 null。调用方法一律 ?.。
  • 函数 ref 忘记处理 null：列表重渲染时 Vue 会先用 null 调一次你的函数再传新元素，el.classList.add 直接抛 Cannot read properties of null。
  • v-for 字符串 ref 的顺序：模板里 ref="xxx" 写在 v-for 内会收集成数组，但官方明确不保证顺序与源数组一致；要精确对应就用函数 ref 按索引/按 key 收集。
  • 组件 ref 空壳：ref 指向的是 <script setup> 组件时，必须子组件 defineExpose 才有内容（见第 3 章）。
  • 把 ref 当响应式状态用：ref 里的 DOM 不参与响应式追踪，改了 DOM 属性视图不会「同步回来」——需要回写状态时，老老实实把值赋给一个 ref。
