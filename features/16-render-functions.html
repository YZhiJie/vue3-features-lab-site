渲染函数与函数式组件 ​

模板的底层：render 函数 ​

Vue 模板最终会被编译成一个返回 VNode 树的 render 函数。 99% 的场景直接写模板即可；但当你需要完全用 JS 的能力动态构造 VNode 时（递归结构、按配置数组生成组件、库级封装），可以手写 render 函数，或使用更轻量的函数式组件。

h()：创建 VNode ​

ts
import { h } from 'vue'

// h(标签/组件, props 对象, 子节点)
h('div', { id: 'x', class: ['a', { b: true }] }, '文本')
h('ul', { onClick: handle }, items.map((it) => h('li', { key: it.id }, it.name)))
h(MyCard, { title: 't' }, {
  default: () => h('p', '默认插槽'),
  footer: () => h('button', '具名插槽'),
})

children 支持三种形态：字符串/数字、VNode 数组、插槽对象{ default: () => ..., 具名: () => ... }（给组件传插槽时用对象形式）。

模板到 h 的常见映射：

模板渲染函数
v-ifif/else 或三元，不想要的分支返回 null
v-forarr.map(item => h('li', { key: item.id }, ...))
@clickonClick: fn；@click.once 用 onClickOnce
:classclass: 'x' / ['x', { y: true }]
<slot>slots.default?.()（调用返回 VNode 数组）
<component :is>h(comp)，comp 本身就是第一个参数
v-modelmodelValue + onUpdate:modelValue

注意：key 加在 h 的第二个参数里（h('li', { key: item.id })）， VNode 创建后不可再改；条件分支返回 null 表示不渲染。

函数式组件：(props, ctx) => VNode ​

函数式组件就是一个返回 VNode 的普通函数：没有实例、没有 响应式状态、没有生命周期，渲染开销更小。

ts
import { h, type FunctionalComponent } from 'vue'

const Heading: FunctionalComponent<{ level: number }> = (props, { slots, emit, attrs }) => {
  return h(`h${props.level}`, attrs, slots.default?.())
}
Heading.props = { level: { type: Number, default: 1 } }
Heading.emits = ['click'] // 显式声明，与对象式组件 emits 等价
Heading.inheritAttrs = false // 需要时关闭自动 attrs 透传

第二个参数 ctx 提供：slots（插槽函数集合）、emit（派发事件）、 attrs（透传 attribute）、expose。props 类型通过 FunctionalComponent<Props> 标注；运行时 props 校验仍要挂载 .props（和普通组件的 props 选项同构）。

有状态的 render 函数：setup 返回函数 ​

组件需要响应式状态、computed、生命周期时，让 setup 返回一个函数， 它就成为该组件的 render：

ts
defineComponent({
  props: { nodes: { type: Array, required: true } },
  setup(props) {
    const selected = ref<string | null>(null)
    return () => h('ul', props.nodes.map(n =>
      h('li', {
        key: n.id,
        class: { active: selected.value === n.id },
        onClick: () => (selected.value = n.id),
      }, n.label),
    ))
  },
})

递归树/菜单是这种写法的经典场景（子节点里 h(当前组件, ...)）。

什么时候才用渲染函数 ​

  • ✅ 递归结构（树、菜单、评论嵌套）；
  • ✅ 配置驱动渲染（后端/用户传入列配置、组件映射表）；
  • ✅ 组件库的无状态包装器（Heading、Badge、布局壳）；
  • ❌ 普通业务 UI —— 模板更易读、有编译期优化（静态提升、补丁标志）， 手写 h 反而绕过了这些优化；
  • ❌ 需要大量状态/生命周期 —— 用对象式/<script setup> 组件， 只在内部局部使用 render 函数。

常见坑（真实踩坑记录） ​

  • 函数式组件里用 ref/reactive：它没有实例，闭包状态在同函数 多次复用时会串。要状态就用 setup 返回渲染函数的对象式组件。
  • 忘了声明 .props：TS 类型有了但运行时把 props 当 attrs 透传/校验缺失；FunctionalComponent<Props> 只管类型，运行时 props 仍要挂载。
  • 插槽当数据用：slots.default 是函数，必须 slots.default?.() 调用才拿到 VNode 数组；空插槽是 undefined，可选链别漏。
  • VNode 复用/修改：h() 产出的 VNode 是一次性描述，不要在多处 复用同一个可变 VNode 或创建后改它的 props；需要复用就封装成函数 每次重新创建。
  • 列表忘 key：map 出的 h 第二个参数给 key，否则动态列表 复用节点时状态错位，和模板 v-for 的 key 完全同理。
  • 事件名写错：render 里是 onClick / onUpdate:modelValue 这种小驼峰 props 键，不是 @click 字符串。
