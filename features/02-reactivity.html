响应式系统精要（Reactivity System） ​

这是什么 ​

ref / reactive 能覆盖日常 90% 的场景，但 Vue 3 的响应式系统还藏着一组「进阶武器」，解决的是性能与控制力两类问题：

  • shallowRef：浅层响应式。只有 .value 整体被替换时才触发更新，内部属性的变化不会被追踪。当你拿着一个 1000 行的大表格数据，深层代理每一行对象是纯浪费。
  • triggerRef：手动喊一嗓子。直接改了 shallowRef 的内部属性后，调它强制触发一次更新，省去「整对象替换」的拷贝成本。
  • customRef：自定义依赖收集（track）与触发更新（trigger）的时机。防抖 / 节流输入框的官方标准解法。
  • effectScope：副作用作用域。把一组 computed / watch / watchEffect 打包，一个 stop() 全部停止——组件卸载时 Vue 内部就是这么自动清理的。
  • toRefs / markRaw：解构 reactive 不丢响应式 / 把对象标记为「永不代理」。
vue
<script setup lang="ts">
import {
  customRef,
  effectScope,
  markRaw,
  shallowRef,
  toRefs,
  triggerRef,
} from 'vue'
</script>

一句话判断用不用它们：默认 ref；数据量大到深层代理成为瓶颈时 shallowRef；想改「更新的时机」时 customRef；想批量管理副作用生命周期时 effectScope。

核心 API 速览 ​

API用途关键点
shallowRef(v)只追踪 .value 的整体替换改内部属性不触发更新；常用于大列表 / 大对象
triggerRef(r)手动触发 shallowRef 更新直接改内部属性后调用它，避免整体替换
customRef(cb)自定义 track / trigger 时机回调收到 (track, trigger)，返回 { get, set }
effectScope()收集作用域内的全部副作用scope.stop() 一次性停止；stop 是终态
toRefs(obj)reactive → 一组 ref解构 / 展开 reactive 时保住响应式
markRaw(obj)标记对象永不被代理大型第三方实例（图表 / 地图）的标准搭档

组合使用：真实的「大表 + 图表」场景 ​

把几个进阶 API 串起来，看真实项目里最常见的组合：

ts
const tableData = shallowRef(fetchBigTable()) // 1000 行大表：只做浅层代理
const chart = markRaw(echartsInstance)        // 第三方实例：永不代理

// 整行替换成本太高时，改内部属性后手动触发
function patchRow(id: number, patch: Partial<Row>) {
  const row = tableData.value.find((r) => r.id === id)
  Object.assign(row, patch)
  triggerRef(tableData)
}

// 页面卸载时把所有副作用一起带走
const scope = effectScope()
scope.run(() => {
  watch(tableData, renderTable)
  watchEffect(() => chart.setOption(buildOption(tableData.value)))
})
onUnmounted(() => scope.stop())

toRefs 则出现在「必须解构」的场合——比如组合式函数返回一个 reactive 对象，调用方想解构又不想丢响应式：

ts
function useMouse() {
  const pos = reactive({ x: 0, y: 0 })
  // ...监听鼠标移动更新 pos
  return toRefs(pos)
  // 调用方：const { x, y } = useMouse() —— x/y 依旧是响应式 ref
}

常见坑（真实踩坑记录） ​

  • shallowRef 改内部属性没反应：rows.value[0].name = 'x' 会静默失败——浅层 ref 只关心 .value 的引用有没有换人。要么整对象替换，要么 triggerRef(rows)。
  • customRef 的 set 里忘写 clearTimeout：每敲一个字母都新建一个定时器，结果是「每个字母触发一次」而不是「停下来才触发一次」。防抖的灵魂是先清再设。
  • customRef 忘记 track / trigger：get 里不调 track()，依赖收集不到——ref 更新了视图也不动；set 里不调 trigger() 同理。两者都是静默失效，控制台不报错。
  • effectScope.stop() 后想「恢复」：stop 是终态，被停掉的 watch 不会随依赖变化重启。要重启就新建一个 scope 并 scope.run(...) 重新收集（参考答案演示了这个写法）。
  • markRaw 之后又想要响应式：被标记的对象放进 reactive 后改属性不触发更新，且没有任何报错。只能删掉 markRaw 补救——所以它只该用在「确定永远不需要响应式」的对象上（如 ECharts 实例）。
  • 对 shallowRef 的期待过头：toRefs 解构 shallowRef 得到的仍是指向同一浅层 ref 的引用，内部属性依旧不是响应式，别指望它救 shallowRef 的深层。
