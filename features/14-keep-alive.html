KeepAlive 组件缓存 ​

这是什么 ​

<KeepAlive> 是 Vue 内置组件，用来缓存不活动的组件实例（连同它们的 DOM 与内部状态）。在多个动态组件之间切换时，默认行为是「切走即卸载、 切回即重建」——输入框内容清空、列表重新请求、定时器重新初始化； 包一层 <KeepAlive> 后，切走的组件只是被停用（deactivate）， 切回来时**激活（activate）**即可，状态原样还在。

vue
<KeepAlive>
  <component :is="currentTab" />
</KeepAlive>

要求：被缓存的是组件，且 KeepAlive 与动态组件之间不要插普通元素， 它需要一个「当前激活的直接子组件」。

生命周期的变化（重点） ​

被缓存后，组件走的是激活/停用而不是挂载/卸载：

时机无 KeepAlive有 KeepAlive
第一次进入onMountedonMounted → onActivated
切走onUnmountedonDeactivated（实例保留）
再切回重新 setup + onMountedonActivated（状态还在）
被 max 淘汰 / exclude 命中——onDeactivated → onUnmounted（真正销毁）

两条实践铁律：

  1. 「每次进入都要做」的副作用放 onActivated：重新拉数据、埋点上报、 滚动复位。onMounted 只在真正创建时执行一次。
  2. 停用后不该跑的东西在 onDeactivated 停掉：定时器、WebSocket、 轮询、音视频播放。否则组件「藏在缓存里」仍在后台空转。

include / exclude / max ​

vue
<!-- 只缓存名字匹配的组件（字符串逗号分隔 / 正则 / 数组） -->
<KeepAlive include="PostsTab,CounterTab" :max="2">
  <component :is="currentTab" />
</KeepAlive>
  • include：只缓存命中的；exclude：命中的不缓存（优先级更高）； 两者都支持 string | RegExp | (string | RegExp)[]。
  • 匹配的是组件名：<script setup> 下名字由文件名推断 （PostsTab.vue → "PostsTab"）；非 SFC 的内联组件需要显式 defineOptions({ name: 'PostsTab' })，匿名组件匹配不上 include。
  • max：缓存实例数上限。超过时按 LRU（最近最少使用） 淘汰 最久没被访问的实例——被淘汰实例会真正 onUnmounted。 本练习把 max 设为 2、依次访问 3 个标签，可在日志里看到淘汰链。

什么时候该缓存 / 不该缓存 ​

  • 该缓存：带筛选/滚动/表单草稿的列表页、多步表单、切走就重新 请求代价高的面板。
  • 要谨慎：实时性强的页面（必须 onActivated 里主动刷新）、 持有大量数据/连接的重型组件（配合 onDeactivated 释放，或直接 exclude）。

常见坑（真实踩坑记录） ​

  • 以为切回来会重新 onMounted 拉数据：缓存后 onMounted 不再触发， 列表永远停在旧数据。需要刷新就用 onActivated（注意首次挂载它也会 触发，别和 onMounted 重复请求）。
  • 缓存的是 DOM 但定时器照跑：切走标签后秒数还在涨、WS 还在收消息， 全是因为没在 onDeactivated 暂停。
  • include 不生效：组件没有 name。<script setup> 靠文件名推断， 把文件重命名为内嵌组件时名字就变了；动态 import 的内联对象组件 要用 defineOptions 显式命名。
  • KeepAlive 里放了多个/普通子节点：v-if + 多个组件分支可以工作， 但中间插入 <div> 会让缓存找不到唯一组件子节点；动态 :is 最稳。
  • max 以为是「最多存活 N 个页面」：它是缓存条目上限，当前正在 显示的组件始终存在；淘汰发生在新实例进缓存、超过上限的瞬间。
  • 在缓存组件上用 key 乱变：:key 每次渲染都变等于强制重建， KeepAlive 完全失效。
