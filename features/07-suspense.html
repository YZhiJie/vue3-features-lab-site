Suspense 与异步组件 ​

这是什么 ​

<Suspense> 是 Vue 3 内置的「异步边界」组件：当子组件的 setup 是异步的 （<script setup> 顶层使用了 await）时，Suspense 会先渲染 #fallback 插槽里的加载态，等异步逻辑完成后无缝切换到真正内容 —— 不再需要手写 v-if="loading" 来回切换。

vue
<Suspense @pending="onPending" @resolve="onResolve" @fallback="onFallback">
  <template #default><Profile /></template>
  <template #fallback>加载中…</template>
</Suspense>

要点：子组件顶层 await 是允许且推荐的 —— 整个 setup 会暂停到 await 完成，期间由父级 Suspense 展示 fallback；但根组件（App.vue） 顶层禁止 await —— 外面没有 Suspense 包裹它时页面会直接白屏。

defineAsyncComponent 是另一件武器：它把「一个懒加载的组件定义」包装成 普通组件来用，加载完成前渲染 loadingComponent。两者分工：

SuspensedefineAsyncComponent
触发方式子组件 async setup（顶层 await）loader 返回 Promise
控制粒度一整个异步边界单个组件
典型场景首屏数据加载完成前整块占位点开才用的重组件、代码分割
真实写法——loader: () => import('./Heavy.vue')

核心 API 速览 ​

API / 写法说明
<Suspense>异步边界，需要 #default 与 #fallback 两个插槽
@pending默认内容进入 pending（即将/正在显示 fallback）时触发
@resolve默认内容全部异步完成、切换渲染时触发
@fallback已渲染的内容被 fallback 替换时触发（再次 pending 时）
timeoutprop：超过指定毫秒才显示 fallback，避免闪烁
onErrorCaptured(fn)捕获异步 setup 抛出的错误（Suspense 没有 @error 事件）
defineAsyncComponent({ loader, loadingComponent, delay })定义异步组件；delay 控制 loading 出现前的等待（默认 200ms）

常见坑（真实踩坑记录） ​

  • 根组件顶层 await 白屏：App.vue 顶层 await 后整个应用变成异步组件， 外面没有 Suspense 就什么都不渲染。沙箱根组件没有 Suspense，所以禁止在 App.vue 顶层 await；子组件里配合 Suspense 使用是标准姿势。
  • 事件名是 @resolve 不是 @resolved：也没有 @error 事件 —— 异步 setup 抛出的错误只会向上冒泡，必须用 onErrorCaptured 接住， 否则控制台出现 unhandled error，且 Suspense 永远停在 fallback。
  • loadingComponent 一闪而过：defineAsyncComponent 的 delay 默认 200ms，加载快时骨架屏根本来不及出现；想让 loading 必现要显式传 delay: 0。
  • Suspense 不是错误边界：它只处理 pending 态，不兜底错误；并且默认 插槽里若有多个 async 组件，「最慢的那一个」决定整个边界的等待时间， 全部完成前一个都不会显示。
  • fallback 频繁闪烁：已渲染的内容再次 pending 时会切回 fallback （触发 @fallback）。轻微刷新场景建议自己管理 loading 状态，或给 Suspense 加 timeout 参数，超过阈值才显示 fallback。
