计算属性与侦听器（computed / watch / watchEffect） ​

这是什么 ​

三者都能「响应变化」，但分工完全不同：

  • computed：派生状态。依赖不变就走缓存，模板里当普通变量用。只做计算，不做副作用。
  • watch：副作用的家。数据变了要「做事」时用它——写日志、发请求、操作 DOM、持久化。
  • watchEffect：自动追踪的副作用。回调里读到谁就追踪谁，立即执行一次；适合「依赖会动态变化」的场景。
  • onWatcherCleanup（Vue 3.5 新增）：在 watchEffect / watch 回调里同步注册清理函数——上一轮副作用被新一轮顶替时自动执行，是防竞态的官方正解。
vue
<script setup lang="ts">
import { computed, watch, watchEffect, onWatcherCleanup } from 'vue'
</script>

核心 API 速览 ​

API / 选项用途关键点
computed(fn)派生状态 + 缓存里头别发请求、别改别的 ref
watch(src, cb, opts)显式依赖的副作用回调拿到 (newVal, oldVal, onCleanup)
watchEffect(cb)自动追踪的立即副作用读到谁追谁；依赖写进分支里要小心
onWatcherCleanup(fn)注册本轮清理函数（3.5）必须同步调用；重跑 / 停止前先执行
immediate: true创建时立即跑一次回调首轮 oldVal 是 undefined
deep: true深入追踪对象内部大对象上开销大；watch reactive 对象本身则隐式 deep
once: true触发一次后自动停止与 immediate 同用时立即执行完就停

watch vs watchEffect：一张表选型 ​

维度watchwatchEffect
依赖显式声明（听谁的写谁）隐式收集（读到谁追谁）
首次执行默认不执行（要 immediate）立即执行一次
新旧值回调拿到 (nv, ov)拿不到旧值
适合表单联动、按字段发请求一堆响应式灌进同一段逻辑

选型口诀：知道听谁的就 watch，说不清听谁的就 watchEffect。但依赖藏在条件分支里时慎用 watchEffect——分支没走到的那次运行不会追踪对应依赖，容易漏。

一个典型竞态的三代解法 ​

搜索联想的竞态：输入「vue」后马上改成「vue3」，两个 800ms 的"请求"都在路上，旧请求后返回就会覆盖新结果。三代解法对比：

ts
// ① 手动记 token（3.0 起就可行）
let latest = 0
watchEffect(() => {
  const id = ++latest
  fakeSearch(keyword.value, (list) => {
    if (id === latest) suggestions.value = list // 过期请求直接丢弃
  })
})

// ② onCleanup 回调参数（3.0 官方写法）
watchEffect((onCleanup) => {
  const timer = setTimeout(fetch, 800)
  onCleanup(() => clearTimeout(timer))
})

// ③ onWatcherCleanup（3.5 新增，语义更直白）
watchEffect(() => {
  const timer = setTimeout(fetch, 800)
  onWatcherCleanup(() => clearTimeout(timer))
})

本章演示用的是 ③。共同思想：新一轮副作用启动前，先把上一轮的「未竟之事」料理干净。

常见坑（真实踩坑记录） ​

  • watch 一个普通属性：watch(profile.address.city, ...) 传进去的是个字符串，永远不触发；要用 getter：() => profile.address.city。
  • ref 包对象默认浅：watch(objRef, cb) 只在 .value 整体替换时触发，改内部属性没反应；要么加 { deep: true }，要么 watch getter（watch reactive 对象本身反而是隐式 deep 的，别记混）。
  • 新旧值是同一个引用：watch 一个对象（或数组）时，push 之后 newVal === oldVal——拿到的是同一个代理，想 diff 得自己留快照。
  • onWatcherCleanup 注册晚了：它必须在回调执行期间同步调用；放进 setTimeout 里再注册，清理函数永远不会被挂上。
  • computed 里做副作用：在 computed 里发请求 / 改别的 ref，缓存机制会让它「有时候不执行」，行为诡异——副作用请去 watch / watchEffect。
  • 忘了 watchEffect 立即执行：它创建时就跑一次（不像 watch 默认等变化），首次跑时依赖还不全（比如还没挂载的 DOM）就会出错。
