同名 v-bind 简写 ​

这是什么 ​

Vue 3.4 给模板带来了「同名简写」：当绑定的变量名与属性名一致时， 值可以省略 —— :data 等价于 :data="data"。要传的 props 越多， 省掉的重复越明显：

vue
<!-- 3.4 之前 -->
<UserCard :user="user" :extra="extra" />
<!-- 3.4 同名简写 -->
<UserCard :user :extra />

它只是书写糖，编译产物完全相同；同一套思路也适用于动态参数 @[eventName]，并且可以和 v-bind="obj" 对象展开混用 （混用时有一条重要的顺序规则，见下）。

三条核心规则 ​

写法含义注意
:data:data="data" 的同名简写变量名必须与属性名完全一致（含大小写）
@[eventName]="fn"动态参数：属性名由表达式决定表达式只能是单个标识符，不能有空格/引号
<UserCard v-bind="obj" :level="v" />对象展开 + 显式绑定混用后面的覆盖前面的，与书写形式无关

关于顺序规则（最容易翻车）：v-bind="obj" 展开后的每个键都算一次 「显式绑定」，覆盖关系只看书写顺序：

vue
<!-- 对象在后：obj.level 赢 -->
<UserCard :level="myLevel" v-bind="{ level: '来自 obj' }" />
<!-- 对象在前：myLevel 赢 -->
<UserCard v-bind="{ level: '来自 obj' }" :level="myLevel" />

常见坑（真实踩坑记录） ​

  • 动态参数里写不了表达式：:[eventName + 'Suffix'] 直接编译报错 —— 动态参数只能是单个标识符；复杂逻辑放 computed 里再传进来。
  • in-DOM 模板的动态参数被小写化：浏览器解析 HTML 时会把属性名转成 小写，:[attrName] 会变成 attrname。只有写在 .vue 文件里 （走 SFC 编译器）才保留大小写 —— 本沙箱正是 SFC 编译，不用担心。
  • 同名简写要求「名字对得上」：const userData = {...} 想传给 :user-data 就不能简写（没有叫 user-data 的变量），只能写 :user-data="userData"。
  • v-bind 对象的覆盖顺序与直觉相反：合并时后者赢 —— 把「默认值对象」 放在显式绑定之后，默认值会悄悄覆盖你的显式值。约定俗成：把 v-bind="defaults" 写在最前面，让显式绑定有机会覆盖它。
  • :data 绑的是「整个对象」：同名简写不会自动展开 —— 子组件如果期望 的是一堆零散 prop，收到的却是一个名为 data 的对象 prop； 需要展开请写 v-bind="data"。
