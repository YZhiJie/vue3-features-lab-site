传送门与过渡动画（Teleport / Transition / TransitionGroup） ​

这是什么 ​

  • Teleport：把一段模板「传送」到组件树之外渲染——模态框、通知、全屏遮罩的标准解法。弹窗长在深层嵌套的组件里，但 z-index 层叠、overflow: hidden 裁剪都不想受父级影响，就传送到 body。
  • Transition：单元素 / 组件的进出场动画。它不写动画，只负责在恰当的时机给元素挂上 / 摘下 class，动画本体用 CSS 写。
  • TransitionGroup：列表的进出场 + FLIP 移动动画，是 <Transition> 的列表版。
  • Vue 3.5 给 Teleport 加了 defer 属性：目标容器在内容之后才渲染时也能等一等再传送。
vue
<template>
  <Teleport to="body">
    <Transition name="modal">
      <div v-if="show" class="mask">…</div>
    </Transition>
  </Teleport>
</template>

核心 API 速览 ​

API / 属性用途关键点
<Teleport to>传送到指定容器to="body" / 任意选择器；目标须已存在
<Teleport defer>目标后出现也能传送（3.5）等 DOM 更新后再解析 to
<Transition name>进出场动画class 前缀 = name，如 name="modal" → .modal-enter-from
appear首次渲染也播放入场动画Transition / TransitionGroup 都可用
mode="out-in"先离场再入场避免新旧元素同帧叠加；in-out 反之
<TransitionGroup tag>列表动画 + 容器标签每项必须稳定唯一 :key；移动动画用 .xxx-move

六个内置 class：*-enter-from（入场起点）、*-enter-active（入场过程）、*-enter-to（入场终点）、*-leave-from、*-leave-active、*-leave-to。

六件套的执行时序 ​

<Transition name="fade"> 在元素插入 / 移除时按固定顺序挂摘 class。入场为例：

text
帧 1：挂 fade-enter-from（起点态） + fade-enter-active（过渡规则）
帧 2：摘 fade-enter-from → 样式开始向终点过渡
过渡结束：摘 fade-enter-active / fade-enter-to，回到正常状态

离场对称：先挂 leave-from（等于当前态）与 leave-active，下一帧摘 leave-from 换 leave-to，过渡结束全部摘掉。Vue 靠监听 transitionend / animationend 判断结束——如果 class 里忘了写过渡/动画，Vue 检测不到时长，动画会瞬间跳完；transition 和 animation 混用时长不一致时，用 type 或 :duration 显式指定。

TransitionGroup 的 FLIP 移动动画 ​

增删时其它列表项的「平滑补位」不是普通 CSS transition 能直接做的（位置跳变没有过渡起点），Vue 内部用 FLIP 技术：记录旧位置 → DOM 更新 → 记录新位置 → 挂 .xxx-move（transition: transform）用反向 transform 从旧位置「滑」过去。因此：

  • .xxx-move 里只写 transform 的过渡，写 all 会干扰离场动画；
  • 离场项必须 position: absolute 脱离文档流，补位才会立刻开始；
  • 唯一 key / absolute / move 三件事少一件，动画就「乱跳」。

常见坑（真实踩坑记录） ​

  • TransitionGroup 用下标当 key：增删后下标错位，动画张冠李戴甚至不播——key 必须是稳定唯一的业务 id。
  • 删了不补位：.list-leave-active 不加 position: absolute 时，被删项占位直到离场结束，其它项等它走完才「瞬移」上去；配 .list-move 才有平滑补位。
  • v-if / v-else 同标签分支没 key：<Transition> 包住两个同标签分支时 Vue 分不清新旧，动画不播或复用错误——给分支加不同的 key。
  • transition 和 animation 混写：Vue 以「先结束的那个」判定动画完成，两者时长不一致会导致提前摘 class；用 type 或 :duration 显式指定。
  • Teleport 目标不存在：to="#xxx" 指向的节点还没渲染就传送会报错——目标在内容之后出现时用 3.5 的 defer。
  • 样式作用域误判：scoped 样式对被 Teleport 走的元素依然生效（data 属性跟着节点走）；但若动画 class 写在「接收方组件」里、节点来自「发送方」，就要考虑非 scoped 或全局样式。
