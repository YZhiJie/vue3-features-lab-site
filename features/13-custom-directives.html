自定义指令（Custom Directives） ​

这是什么 ​

除了内置指令（v-model / v-show / v-bind ……），Vue 允许你注册 「自定义指令」——它是复用涉及普通元素的底层 DOM 访问逻辑的机制。

Vue 提供了三种复用代码的手段，分工不同：

手段侧重典型场景
组件构建模块（结构 + 状态 + 视图）卡片、表单、弹窗
组合式函数有状态的逻辑复用useFetch、useTimer
自定义指令普通元素上的底层 DOM 操作聚焦、点击外部、tooltip、权限禁用

在 <script setup> 中，任何以 v 开头的驼峰变量都会自动成为指令： const vFocus = { ... } 在模板里直接写 v-focus，无需注册。

指令钩子 ​

指令定义对象可以提供 7 个与组件生命周期相似的钩子（全部可选）：

钩子调用时机常用操作
created元素 attribute / 事件监听器应用之前提前改 attribute
beforeMount元素插入 DOM 之前—
mounted元素及子节点挂载完成聚焦、addEventListener、创建浮层
beforeUpdate元素自身更新之前（新 VNode 应用前）读旧 DOM 状态
updated元素及子节点更新完成根据新 binding.value 同步 DOM
beforeUnmount元素卸载之前（此时 DOM 还在）大多数清理写这里
unmounted元素卸载完成移除只与指令自身相关的监听/节点

钩子参数 ​

  • el：指令绑定的真实 DOM 元素。
  • binding：对象，包含
    • value：传给指令的值，如 v-x="1+1" 里是 2；
    • oldValue：上一次的值，仅 beforeUpdate / updated 可用（无论值是否变化都有）；
    • arg：参数，v-x:foo 里是 "foo"，支持动态写法 v-x:[arg]；
    • modifiers：修饰符对象，v-x.foo.bar 里是 { foo: true, bar: true }；
    • instance：使用该指令的组件实例；
    • dir：指令定义对象本身。
  • vnode / prevVnode：绑定元素对应的底层 VNode（prev 仅更新钩子可用）。

除 el 外参数都是只读的。需要在钩子之间共享数据，官方推荐用 el.dataset；要共享的是函数、定时器这类无法序列化的资源时，可以挂在 元素的自定义属性上（如 el.__clickOutside），但必须在卸载钩子中清掉。

函数简写 ​

只需要在 mounted 和 updated 做同一件事时，直接传一个函数：

ts
// 等价于 { mounted: fn, updated: fn }
const vColor: Directive<HTMLElement, string> = (el, binding) => {
  el.style.color = binding.value
}

需要多个值时传对象字面量即可：v-demo="{ color: 'white', text: 'hi' }"， binding.value.color 直接可取。

注册方式 ​

  • 局部：<script setup> 里的 vXxx 变量；或非 setup 下的 directives: { focus: {...} } 选项。
  • 全局：app.directive('focus', { ... })，所有组件可用。 全局指令的类型通过扩展 vue 的 GlobalDirectives 接口补充。

TypeScript 类型 ​

ts
import type { Directive } from 'vue'

// 泛型依次是：元素类型、binding.value 的类型
const vClickOutside: Directive<HTMLElement, () => void> = { ... }

清理原则：谁注册，谁注销 ​

指令最常见的 bug 是泄漏：mounted 里 addEventListener / setInterval / 新建浮层节点，却忘了在 beforeUnmount 或 unmounted 里反向清理。组件反复挂载/卸载后，监听器不断堆积，后台逻辑越跑越多。

本练习右侧的「生命周期日志」面板就是用来验证这一点的 —— 每次 mounted 注册的资源，都要能在日志里找到对应的 unmounted 清理记录， 成对出现。

关于网传的「3.5 钩子返回 cleanup 函数」：你可能在网上看到 mounted() { return () => cleanup() } 这种写法，称 cleanup 会在 卸载时自动调用。Vue 3.5（含最新 3.5.42）并未实现该特性—— 运行时 invokeDirectiveHook 会直接丢弃钩子的返回值，写了也不会 执行。那是一个尚未落地的 RFC 提案。3.5 里请老老实实用 mounted/unmounted 成对清理（本练习的写法）。可以用沙箱验证： 给指令钩子 return 一个函数，卸载时日志区不会有任何动静。

常见坑（真实踩坑记录） ​

  • 只注册不注销：组件卸载后 document 上的监听还在，再次挂载又注册 一个，点一下触发 N 次。验证方法：反复开关面板/重挂载元素，看日志 是否成对、行为是否叠加。
  • clickOutside 打开即关闭：打开面板的点击事件还在冒泡，指令在 mounted 里同步注册监听，同一事件随即命中「外部」。setTimeout(0) 延后注册即可（参考答案的写法）。
  • 把 updated 当 mounted 用：oldValue 只在更新钩子中有值； mounted 里访问是 undefined。
  • 在多根组件上用指令：指令会落在根节点（类似 attrs 透传）， 多根（fragment）组件无法确定落点，指令被忽略并报警告；也不能像 attrs 那样用 v-bind="$attrs" 转给内部元素。
  • 滥用指令：需要响应式状态或模板结构时，指令是错误工具—— 优先用 v-bind 声明式绑定、组合式函数或组件。指令只服务于 「不做底层 DOM 操作就实现不了」的功能。
  • SSR：自定义指令不会在服务端执行 DOM 钩子；需要在 SSR 输出上 声明 attribute 时，实现对象式指令的 getSSRProps(binding, vnode)。
