组合式 API（Composition API） ​

这是什么 ​

组合式 API 是 Vue 3 最重要的编程范式变化。它允许你按逻辑关注点（而不是选项类型）组织代码：一个功能的所有状态、计算、副作用都写在一起。

vue
<script setup lang="ts">
// <script setup> 是组合式 API 的语法糖：
// 顶层代码就是 setup() 函数体，声明的变量直接在模板可用
import { computed, onMounted, reactive, ref } from 'vue'
</script>

对比 Options API（Vue 2 风格）：data / methods / computed / mounted 被拆散在不同选项里，功能一多就要来回跳；组合式 API 把它们聚拢，且天然获得完整的 TypeScript 类型推导。

核心 API 速览 ​

API用途关键点
ref(v)包装任意类型为响应式引用JS 中读写要 .value；模板中自动解包
reactive(obj)把对象变成响应式代理访问属性无需 .value；不能整体替换
computed(fn)派生状态，依赖不变时走缓存是 ref，使用方式与 ref 一致
onMounted(fn)DOM 挂载后执行的副作用可安全访问 DOM / 发起请求
watch(src, cb)侦听响应式变化执行副作用详见第 5 章

ref 与 reactive 怎么选？ ​

  • 默认用 ref：类型一致（.value 心智统一）、可以整体替换、支持任意类型。
  • reactive 适合聚合一组相关字段且不会整体替换的本地状态（表单对象等）。
  • 最大的坑：对 reactive 对象做解构或展开会丢失响应式（需要 toRefs 补救）：
ts
const state = reactive({ x: 1, y: 2 })
const { x } = state        // ❌ x 是普通数字，失去响应式
const { x } = toRefs(state) // ✅ x 是 Ref，保持响应式

常见坑（真实踩坑记录） ​

  • 忘记 .value：count + 1 拿到的是 NaN（count 是 Ref 对象）。
  • 模板里写 .value：模板自动解包，写 &#123;&#123; count.value }} 反而报错。
  • reactive 整体替换：state = { ...newObj } 直接把响应式代理扔掉了；要么改属性，要么改用 ref。
  • 解构 reactive：见上文 toRefs。
  • 顶层 await：<script setup> 顶层 await 会把组件变成异步组件，需要 <Suspense> 包裹（见第 7 章）——沙箱根组件没有 Suspense，请不要在 App.vue 顶层使用。
